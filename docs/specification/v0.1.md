# AI Context Engine v0.1 Specification

## 1. Overview

AI Context Engine v0.1 converts a local software repository into structured AI-readable project context.

The primary output is:

```text
.ai-context/
```

The primary command is:

```bash
ai-context init [PATH]
```

---

# 2. MVP Goal

The goal of v0.1 is:

> Given a local Java or Python repository, automatically generate a structured `.ai-context` directory.

The generated context should contain:

- project metadata
- project type
- languages
- build tools
- frameworks
- modules
- dependencies
- generation metadata

---

# 3. Supported Project Types

## 3.1 Java

Support:

- Maven
- Single Module Project
- Multi Module Project
- Spring Boot basic detection

Recognized files:

```text
pom.xml
```

---

## 3.2 Python

Support:

- pyproject.toml
- requirements.txt
- setup.py
- basic Python package structure

Basic framework detection:

- FastAPI
- Django
- Flask

---

## 3.3 Unknown Project

Unknown repositories should still generate basic context.

The system should not fail simply because a project type cannot be recognized.

---

# 4. CLI Specification

## 4.1 Command

```bash
ai-context init
```

Scan the current directory.

```bash
ai-context init .
```

Scan the specified current directory.

```bash
ai-context init /path/to/project
```

Scan the specified repository.

---

## 4.2 Options

### `--force`

Overwrite an existing context directory.

Example:

```bash
ai-context init --force
```

---

### `--output PATH`

Specify a custom output directory.

Example:

```bash
ai-context init --output ./generated-context
```

Default:

```text
<repository>/.ai-context
```

---

### `--verbose`

Show detailed execution logs.

Example:

```bash
ai-context init --verbose
```

Example output:

```text
Scanning repository...
Detecting project type...
Detecting modules...
Analyzing technology stack...
Analyzing dependencies...
Generating context...
```

---

# 5. Repository Root Detection

The system should determine the repository root.

Priority:

```text
1. Git repository root
2. Build configuration root
3. User-provided path
```

Recognized project indicators:

```text
.git
pom.xml
pyproject.toml
setup.py
requirements.txt
```

---

# 6. Java Analysis

## 6.1 Maven Project Detection

The engine should detect Maven projects through:

```text
pom.xml
```

The engine should extract when available:

- groupId
- artifactId
- version
- packaging

---

## 6.2 Maven Multi Module Detection

Given:

```text
project/
│
├── pom.xml
│
├── service-a/
│   └── pom.xml
│
└── service-b/
    └── pom.xml
```

The engine should identify:

```text
service-a
service-b
```

as modules.

---

## 6.3 Spring Boot Detection

Spring Boot should be detected through either:

```text
spring-boot-starter
```

dependency information.

Future versions may additionally support annotation-based detection.

For v0.1, dependency-based detection is sufficient.

---

# 7. Python Analysis

## 7.1 Project Detection

Recognize:

```text
pyproject.toml
setup.py
requirements.txt
```

---

## 7.2 Extracted Information

When available:

- project name
- Python version
- dependencies
- package directories

---

## 7.3 Framework Detection

Detect frameworks through dependency names.

Recognized frameworks:

```text
fastapi
django
flask
```

---

# 8. Module Detection

## 8.1 Java Modules

Java modules are identified primarily through Maven modules.

Example:

```xml
<modules>
    <module>service-a</module>
    <module>service-b</module>
</modules>
```

---

## 8.2 Python Modules

Python package roots should be detected through:

```text
__init__.py
```

and common:

```text
src/
```

layout.

---

# 9. Dependency Analysis

## 9.1 Java

Analyze Maven dependencies.

The engine should identify:

- dependency artifactId
- internal module dependencies

Example:

```text
order-service
       │
       ▼
payment-service
```

---

## 9.2 Python

Analyze dependencies from:

- requirements.txt
- pyproject.toml
- setup.py when practical

---

## 9.3 Non Goals

v0.1 does not analyze:

- method calls
- class relationships
- REST calls
- Feign calls
- message queues
- database relationships

---

# 10. Output Structure

The default output directory:

```text
.ai-context/
│
├── project.json
├── modules/
│   ├── module-a.json
│   └── module-b.json
├── dependencies.json
└── manifest.json
```

---

# 11. Context Schema

## 11.1 project.json

Example:

```json
{
  "schemaVersion": "0.1",
  "name": "mall-system",
  "repository": {
    "root": "."
  },
  "project": {
    "languages": [
      "Java"
    ],
    "buildTools": [
      "Maven"
    ],
    "frameworks": [
      "Spring Boot"
    ]
  }
}
```

---

## 11.2 Module Context

Example:

```json
{
  "schemaVersion": "0.1",
  "name": "order-service",
  "path": "order-service",
  "language": "Java",
  "type": "application",
  "build": {
    "tool": "Maven"
  },
  "frameworks": [
    "Spring Boot"
  ],
  "dependencies": [
    "payment-service"
  ]
}
```

---

## 11.3 dependencies.json

Example:

```json
{
  "schemaVersion": "0.1",
  "nodes": [
    {
      "id": "order-service"
    },
    {
      "id": "payment-service"
    }
  ],
  "edges": [
    {
      "from": "order-service",
      "to": "payment-service",
      "type": "module-dependency"
    }
  ]
}
```

---

## 11.4 manifest.json

Example:

```json
{
  "schemaVersion": "0.1",
  "generator": {
    "name": "ai-context",
    "version": "0.1.0"
  },
  "generatedAt": "2026-08-30T00:00:00Z",
  "repository": {
    "branch": "main",
    "commit": "abc123"
  }
}
```

---

# 12. Error Handling

## Path Not Found

Example:

```text
Error: Repository path does not exist
```

The command should exit with a non-zero exit code.

---

## Unsupported Project

Example:

```text
Warning: Unsupported project type
```

The engine should still generate basic context when possible.

---

## Existing Context

Default behavior:

```text
Error: .ai-context already exists
```

Using:

```bash
ai-context init --force
```

allows regeneration.

---

# 13. Deterministic Requirements

For the same repository state, repeated execution should produce semantically equivalent context.

The following must remain stable:

- project type
- module list
- dependency graph
- detected frameworks
- detected build tools

The following may change:

```text
generatedAt
```

---

# 14. Explicit Non Goals

The following are outside v0.1:

- LLM analysis
- Vector Database
- Embedding
- RAG
- MCP Server
- Agent Framework
- Workflow Engine
- File Watcher
- Incremental Update
- Graph Database
- full AST analysis
- call graph analysis
- semantic code understanding

---

The project must include:

```text

Integration Test
Golden Test
```

```text
tests/fixtures/
├── java-single-module/
├── java-multi-module/
├── python-simple/
├── python-fastapi/
```

Golden testing:

```text
Fixture Repository
        │
        ▼
AI Context Engine
        │
        ▼
Generated Context
        │
        ▼
Compare with Golden Context
```

- [ ] dependency graph can be generated
- [ ] manifest can be generated

- [ ] integration tests pass
- [ ] golden tests pass

- [ ] README is complete
